# ADR-0002: DB 스키마는 Flyway 마이그레이션으로만 바꾼다

- 상태: 채택
- 날짜: 2026-10-30

## 배경
JPA는 엔티티를 보고 테이블을 자동으로 만들거나 고칠 수 있다(`ddl-auto: update`). 편하지만 운영 DB에서 언제 무엇이 바뀌었는지 추적할 수 없고, 컬럼 삭제·이름 변경 같은 변경은 안전하게 하지 못한다.

## 결정
- 스키마는 `src/main/resources/db/migration/V{번호}__{설명}.sql` 파일로만 바꾼다.
- 이미 적용된 마이그레이션 파일은 수정하지 않는다. 고칠 것이 있으면 다음 번호 파일을 추가한다.
- JPA는 `ddl-auto: validate`로 두어, 엔티티와 실제 스키마가 다르면 애플리케이션이 **시작하지 않게** 한다.

## 검토한 대안
| 대안 | 기각 이유 |
| --- | --- |
| `ddl-auto: update` | 변경 이력이 없고, 운영에서 예측 불가능 |
| Liquibase | 기능은 충분하지만 SQL을 직접 쓰는 Flyway가 학습과 리뷰에 더 직관적 |

## 결과
- 스키마 변경이 코드 리뷰 대상이 되고, 로컬·CI·운영 DB가 같은 순서로 같은 상태가 된다.
- CI의 통합 테스트가 실제 PostgreSQL에 모든 마이그레이션을 적용하므로 SQL 오류를 머지 전에 잡는다.
