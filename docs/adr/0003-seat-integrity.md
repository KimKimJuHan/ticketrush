# ADR-0003: 중복 판매의 최종 방어선은 DB 제약조건으로 둔다

- 상태: 채택
- 날짜: 2026-10-30

## 배경
요구사항 N1: 한 좌석은 한 회차에서 한 번만 확정된다. 동시성 제어(락, Redis 등)는 7~8주차에 실험하며 바뀔 예정이고, 실험 중에는 애플리케이션 로직이 틀릴 수 있다.

## 결정
애플리케이션의 동시성 제어와 별개로, DB에 **취소되지 않은 판매는 좌석당 1건**이라는 제약을 건다.

```sql
CREATE UNIQUE INDEX ux_reservation_items_active_seat
    ON reservation_items (performance_seat_id)
    WHERE cancelled_at IS NULL;
```

일반 유니크 제약이 아니라 **부분 유니크 인덱스**를 쓴 이유: 취소된 판매 기록은 남겨야 하고, 취소된 좌석은 다시 팔 수 있어야 한다. 조건(`WHERE cancelled_at IS NULL`)에 맞는 행끼리만 유일성을 검사한다.

## 결과
- 로직 버그나 경쟁 조건이 있어도 두 번째 판매는 DB 오류로 실패한다. 애플리케이션은 이를 409 `SEAT_UNAVAILABLE`로 변환한다.
- 6주차 실험에서 "락이 없을 때 **선점**은 중복으로 일어나지만, **판매**는 DB가 막는다"는 차이를 측정할 수 있다. 다만 막히는 순간 사용자는 결제 직전 실패를 겪으므로, 제약조건만으로는 좋은 사용자 경험이 되지 않는다. 그래서 선점 단계의 동시성 제어가 따로 필요하다.
